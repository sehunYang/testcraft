# TestCraft — 교사용 출제 작업실

평가의 의도를 담아, 시험을 빚다. *Crafting assessments with purpose.*

## 실행

현재 PC: 프로젝트의 TestCraft 아이콘 **TestCraft 바로가기**(`TestCraft.lnk`)를 더블클릭합니다. `TestCraft.cmd`를 직접 실행해도 됩니다. 서버가 준비되면 브라우저가 `http://127.0.0.1:8765`를 엽니다. 서버는 숨겨진 별도 프로세스로 실행되어 명령 프롬프트가 작업 표시줄에 남지 않습니다. 이미 실행 중이면 같은 서버를 재사용합니다. 작업은 파일에 저장되어 다음 실행에 이어집니다. 시작에 실패하면 오류 창에서 `.runtime/studio-server.stdout.log`와 `.runtime/studio-server.stderr.log` 위치를 확인할 수 있습니다.

Windows는 `.cmd` 파일 자체에 개별 아이콘을 지정할 수 없으므로, 같은 실행기에 연결된 바로가기에 사이트 파비콘과 동일한 아이콘을 적용했습니다. 폴더를 이동한 뒤에는 `.cmd`를 한 번 실행하면 바로가기 경로가 갱신됩니다. 사이트 아이콘 원본은 `app/static/icons/itemcraft.svg`이며 `node tools/build_brand_assets.cjs`로 PNG·ICO를 다시 만듭니다. 메타데이터는 로컬 앱 주소를 사용하므로 외부 공개 배포 시 공유 이미지 주소와 검색 노출 설정을 변경해야 합니다.

다른 PC에서 설치하려면 Python 3.11 이상과 Node.js 20 이상을 준비하고 프로젝트 폴더에서 다음을 실행합니다.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm install
.venv\Scripts\python run_studio.py
```

현재 PC에서는 Codex에 포함된 Python·Pillow·openpyxl·Node·Sharp를 재사용하고 SymPy는 `.runtime/packages`에 설치했습니다. 실행기는 `.venv`를 우선합니다. 환경을 새로 구성할 때 위 설치 명령을 사용하세요. HWP 변환이 필요하면 한글이 설치된 Windows에서 같은 Python 환경에 `pip install pyhwpx`를 추가합니다.

## Codex / Claude 연결

웹앱은 API 키를 받거나 저장하지 않습니다. 로그인된 CLI를 별도 프로세스로 호출하고 JSON 결과를 받아 적용합니다. 일반 터미널에서 Codex는 `codex login`, Claude Code는 `claude`로 설치·로그인을 확인합니다. CLI 경로는 PATH와 일반 설치 위치에서 찾습니다. 다른 위치는 `QUESTION_MAKER_CODEX_PATH` 또는 `QUESTION_MAKER_CLAUDE_PATH` 환경변수에 실행 파일의 절대 경로를 지정하세요. Windows의 npm 래퍼는 패키지 내부 `.exe` 또는 `cli.js`를 찾아 직접 실행합니다. 프롬프트를 셸 문자열로 전달하지 않습니다.

화면 오른쪽 위 **AI 연결 설정**에서 제공자를 선택합니다. 모델 이름을 비우면 해당 CLI 기본 설정을 사용합니다. 현재 PC에서 Codex와 Claude Code 모두 기존 로그인으로 실제 JSON 결과 수신을 확인했습니다. Codex는 문항·해설·SVG 생성과 SymPy 검산·PNG 렌더링까지 확인했습니다.

- Codex: `exec --sandbox read-only --output-schema … --output-last-message … --json`
- Claude Code: `-p --output-format json --json-schema … --tools "" --no-session-persistence`
- 프롬프트는 stdin으로 전달하며 셸 명령 문자열에 삽입하지 않습니다.
- CLI에게 원본 카드·출제 지침·선화 지침을 전달합니다. 응답을 검사한 뒤 앱이 회차 데이터에 반영합니다.
- 회차마다 한 작업만 실행하며 작업 중 해당 회차 편집을 잠급니다. 작업 취소와 20분 제한 시간을 지원합니다. 전체 작업은 문항별로 저장하므로 실패 전 완료된 문항은 보존합니다. 성공한 문항은 AI 생성 요청이 No로 바뀌고, 실패·취소로 미완료인 문항은 Yes로 남습니다. 실패가 있어도 다음 문항을 계속 처리하며, 일괄 생성 버튼을 다시 누르면 Yes 문항만 재시도합니다.
- CLI 로그인, 계정 사용량, 모델 접근 권한은 CLI 자체 조건을 따릅니다. 앱에 API 키가 없어도 선택한 서비스에 문항 내용은 전송됩니다.

공식 실행 규격: [Codex 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [Claude Code 프로그램 실행](https://code.claude.com/docs/en/headless).

## 사용 순서

**내 시험** 홈에서 제목과 수정일을 보고 작업을 이어갈 수 있습니다. 시험을 열면 상단의 설계 → 검토 → 그림 → 출력 탭으로 이동합니다. 설계에서 작성 방식을 선택하고 입력한 뒤, 검토에서 문항·정답·해설을 다듬습니다. 좌측 메뉴는 상단 ☰ 버튼으로 접어 편집 공간을 넓힙니다. **도움말**은 현재 단계에 맞는 설명부터 펼쳐 줍니다.

Clipo 교사 화면의 시각 체계를 참조하되, [교사 페르소나 7점 평가](UIUX-교사-루브릭.md)를 통과한 요소만 적용했습니다.

1. **새 시험 만들기**에서 제목과 과목을 선택하고 빈 카드, 엑셀 업로드, 기존 회차 중 하나를 선택합니다. 원본 파일은 변경하지 않습니다.
2. **설계 → 문항 추가**에서 **AI로 초안 만들기** 또는 **직접 작성하기**를 선택합니다. AI 초안은 성취기준·문항 유형·난이도·핵심 아이디어 네 항목만 필수이며, 필요한 자료는 선택 사항으로 대강 적습니다. 예를 들어 “(가)·(나) 두 그림과 실험 표”라고 요청할 수 있습니다. **생성 대기에 추가**로 저장한 뒤 설계 목록으로 돌아옵니다. 직접 작성은 같은 설계 단계에서 문두·발문·보기·선택지·정답·해설과 복합 자료를 입력하고 **문항 저장**을 누릅니다. 미완성 직접 작성 초안도 저장할 수 있으며 자동 생성 대상으로 추가되지 않습니다. 배점은 나중에 검토·배점 영역에서 정합니다. 성취기준은 선택한 과목 안에서만 고를 수 있고, 다른 과목 코드가 섞인 엑셀은 오류 문항을 안내합니다. 화면 상단에는 문항 유형별·상중하별·정답별 현황과 사용 중인 성취기준 개수를 표시합니다.
3. 설계 목록의 **AI 초안 N문항 생성**을 누르면 대기 문항을 한 번에 작성합니다. 입력 저장만으로 AI가 실행되지는 않습니다. 성공한 문항만 요청이 No로 바뀌며, 실패한 문항은 Yes로 남아 다시 처리할 수 있습니다. 최초 작성 방식은 별도로 보존하므로 생성이 끝난 AI 문항도 AI 작성 문항으로 남습니다. 생성 결과와 직접 작성한 문항은 같은 검토 화면에서 수정합니다. 이후 AI 수정 요청도 사용할 수 있습니다. 이 단계에서는 문항·해설·자료 제작 계획까지만 작성하며 실제 그림 생성과 배점 확정은 뒤에서 진행합니다.
4. 문두, 발문, 보기, 답지, 정답, 해설과 자료를 검토하고 필요한 부분을 직접 수정합니다. 문항별 **검토 완료**는 배점을 정하기 전에도 사용할 수 있습니다. 계산 문항은 검산식을 확인한 후 **계산 확인**을 진행합니다. 식이 일치하지 않으면 결과를 보고 취소하거나 **오류를 확인했고 그래도 승인**을 선택합니다. 설계 목록의 배점·정답 번호는 읽기 전용이고, 실제 변경은 검토·배점 영역에서 합니다. 문두가 비어 있을 때 핵심 아이디어는 학생용 미리보기에 대신 나오지 않습니다.
5. 문항을 검토한 뒤 **배점** 패널에서 점수를 직접 입력하거나, 권장안을 미리 보고 **권장 배점 적용**을 눌러 반영합니다. 빈 배점은 자동으로 채워지지 않습니다. 합계 100점을 맞추고 배점 변경 문항을 다시 검토한 뒤 **문항카드 전체 승인**을 누릅니다. 승인 전 실제 그림 생성·업로드·적용과 시험지 출력은 서버에서도 차단합니다. 승인 후 그림마다 유형과 제작 범위를 확인하고 **제작 계획 확인**을 누릅니다. 이 확인은 저장과 별도이며 기존 그림을 다시 만들지 않습니다. 그림의 수치·객체·라벨·정답 유도 여부를 확인하고 **그림 + 글씨 최종 확정**을 누릅니다.
6. **검토 · 출력**에서 누락과 미승인을 해결한 뒤 **시험지 · 답지 파일 생성**을 누릅니다. 총점이 100점이 아니면 출력되지 않습니다. 문항 수가 바뀌면 **100점 자동 배점**을 다시 적용하세요.
7. 앱이 학교 양식에 맞춘 HML을 내부 원본으로 만들고, 이 PC에 설치된 한컴오피스 한글을 별도 숨김 프로세스로 실행해 수식을 재계산한 뒤 **학생용·교사용 시험지와 정답·해설 HWPX**로 저장합니다. 앱에 한글 엔진이 포함되는 방식은 아니며, Windows용 한글이 설치되어 있어야 합니다. 사용자가 열어 둔 한글 문서에는 연결하지 않습니다.
8. 학생용·교사용 시험지 HWPX, 정답·해설 HWPX, 카드 XLSX 또는 전체 ZIP을 받습니다. 학생용은 정답 형광펜 요소를 제거하고 교사용은 유지합니다. 내부 HML은 보존하되 다운로드와 ZIP에는 넣지 않습니다. 세 HWPX의 패키지·수식·그림 보존을 확인한 뒤 전체 ZIP을 제공합니다. 한글이 없거나 변환에 실패하면 완료로 표시하지 않고 **한글 연결 확인** 또는 **HWPX 다시 만들기**를 안내합니다. 최종 인쇄 배치는 받은 HWPX를 한글에서 열어 확인하세요. 이전 출력 기록도 HML 원본이 남아 있으면 HWPX로 변환할 수 있습니다.

AI 초안의 자료 요청에서 **그림·글상자·표**를 여러 개 함께 선택할 수 있습니다. 아무것도 선택하지 않으면 AI가 판단하며, 종류를 지정하면 새 자료는 그 종류로만 작성합니다. 그림 유형도 선택 사항입니다. **strict**는 SVG 고정 영역만, **flexible**은 창작 허용 영역만, **mixed**는 서로 다른 요소를 두 영역에 나눕니다. 그림을 제외한 자료 종류만 선택하면 그림 유형은 비워집니다. 이 요청은 기존 자료의 ID·순서·교사 지정 그림 유형을 바꾸지 않습니다.

**세부 형식**(선택 사항): 문항 유형 아래에서 그 과목·유형에 맞는 평가원 꼴을 고를 수 있습니다. 예를 들어 사회의 "지도 위치 대응형", 역사의 "연표 칸 고르기형", 영어의 "요약문 빈칸 (A)(B)형"입니다. 4종 유형은 그대로이고, 고르면 AI가 그 꼴의 자료 배치·발문·선지로 문항을 씁니다. 고르지 않으면 유형만 따릅니다. 유형을 바꿔 맞지 않게 된 형식은 자동으로 비워집니다. 형식 목록은 `app/question_formats.json`이며 `instructions/기출-형식-매뉴얼/`에서 뽑았습니다. 형식을 바꿔도 문항 승인은 풀리지 않습니다. 이미 쓴 문항에 반영하려면 AI 수정 요청을 하세요.

AI 문항·수정·그림·그림 계획·글씨 생성 중에는 **대기 모달**에서 현재 처리 내용과 진행 수를 확인합니다. 실행 중에는 Esc나 배경 클릭으로 닫히지 않으며, **생성 취소**로 중지를 요청할 수 있습니다. 완료·실패·취소가 확인되면 자동으로 닫힙니다. 연결을 확인하지 못하면 다시 조회한다는 안내를 표시하고, 반복 오류 뒤 **상태 창 접기**를 선택해도 상태 조회는 계속됩니다.

## 그림과 글씨의 분리·편집

SVG 객체의 **위쪽 원형 손잡이**를 끌면 회전합니다. 기본값은 **15° 단위 스냅**이며 속성의 **−15° / ＋15°** 버튼이나 상대 회전 각도 입력도 사용할 수 있습니다. **Alt**를 누르면 자유롭게 회전·이동·크기 조절합니다.

캔버스 아래의 **객체 위치 / 같은 너비·높이 / 15° 회전**으로 스냅을 각각 설정합니다. 위치·치수 스냅은 **스마트 정렬**이 켜져 있을 때 작동합니다. 다른 객체의 가장자리·중앙에 가까워지면 분홍 가이드가 나타나고, 크기 손잡이를 끌어 다른 객체의 너비·높이에 가까워지면 동일 치수로 맞춰집니다. Shift 또는 비율 유지를 켜면 가로세로 비율을 보존합니다. 감지 거리는 화면 기준 약 7px이며, 숨긴 객체는 제외합니다. 가이드와 치수 표시는 편집 화면에만 나타납니다.

**자료 디자인**은 왼쪽 레이어, 중앙 캔버스, 오른쪽 속성 패널로 구성됩니다. **배경 생성·가져오기 / 기본 도형·격자 설정**을 펼치면 기존 생성·변환·기본 도형 옵션이 나옵니다. 그림을 객체로 변환한 뒤 캔버스에서 선·사각형·타원·펜으로 직접 그릴 수 있습니다. Shift+클릭이나 빈 곳에서 상자를 끌어 도형과 글씨를 함께 선택하고 정렬·이동하세요. 글씨는 크기·회전 손잡이로도 조절합니다.

레이어의 이름·잠금·표시 상태와 순서를 편집할 수 있습니다. 같은 영역 안에서 레이어를 드래그해 순서를 바꿉니다. 글씨는 배경 위에 유지되며 숨긴 글씨는 최종 PNG에서 제외됩니다. 실행 취소는 도형과 글씨를 함께 되돌립니다. 손 도구 또는 Space+드래그로 이동하고, Ctrl+휠로 확대합니다. 단축키는 캔버스에 초점이 있을 때 작동합니다. 자세한 기능과 오픈소스 출처는 [자료 디자인 안내](자료-디자인-오픈소스.md)에 정리했습니다.

상단 현황은 총 문항 수와 문항 유형·난이도·정답 분포를 구분해 보여줍니다. 상대적으로 많은 수치는 주황 숫자와 ↑, 적은 수치는 파랑 숫자와 ↓로 표시하며, 입력 초반에는 색상 안내를 유예합니다. ⓘ에서 판단 기준을 확인할 수 있습니다. 균등 비중은 참고용이며 출제 의도를 우선하세요. 성취기준은 실제 사용한 코드만 한 줄에 표시하고, 나머지는 +N과 더 보기에서 확인합니다. 작은 화면에서는 통계 그룹이 줄을 바꾸어 표시됩니다.

설계 목록의 작업 열에는 **복제**와 **삭제** 아이콘이 바로 표시됩니다. 복제하면 원본 바로 다음 번호에 출제 기준·문항 내용·자료·편집 가능한 그림과 글씨를 복사합니다. 복사본의 그림 파일은 별도로 저장되며, 복사본은 배점 미정·검토 대기·AI 요청 해제로 시작합니다. 복제 후 전체 출제안을 다시 승인해야 합니다. 삭제 아이콘을 누르면 문항 번호와 아이디어를 확인한 뒤 삭제하거나 취소할 수 있습니다. 삭제 저장에 실패하면 초안을 보존하고 다시 저장할 수 있습니다.

- **strict**: SVG 규칙만 작성합니다. 창작 허용 영역은 빈칸입니다.
- **flexible**: 창작 허용 영역만 작성합니다. SVG 규칙은 빈칸입니다.
- **mixed**: 두 영역에 서로 다른 요소를 지정합니다. 각 줄은 `floor: 수평 바닥선`처럼 요소ID와 설명으로 적으며 양쪽에 같은 ID를 사용할 수 없습니다. 의미상 같은 물체를 다른 ID로 중복 지정하지 않았는지도 확인하세요.

그림 프롬프트에는 글씨·물리량·수식·단위·라벨을 넣지 않습니다. 필요한 표기는 **이미지 글씨 프롬프트**의 물리량·수식·한글 칸에 내용과 위치를 적습니다. 물리량과 수식은 LaTeX(예: `v_0`, `\frac{1}{2}mv^2`), 한글은 평문으로 입력합니다.

자료 그림은 한 번에 한 단계만 표시합니다. 상단 단계 버튼 또는 하단 이전·다음 버튼으로 이동하며, 단계 이동 전에 변경 내용을 저장합니다.

한 문항에는 그림·글상자·표 자료를 여러 개 순서대로 둘 수 있습니다. **문항** 편집의 자료 목록에서 종류·이름(예: (가), (나))·내용을 바꾸고 위아래 버튼으로 시험지 순서를 정합니다. 자료가 없는 기존 단일 자료도 그대로 열리며, 자료 목록을 편집하거나 새 자료를 추가할 때 기존 내용이 목록으로 옮겨집니다. 전체 미리보기는 글상자·표·그림을 이 순서대로 보여 줍니다. 그림 선택기는 (가), (나) 사이를 전환하고, 각 그림의 계획·배경·글씨·편집 객체·확정 상태는 따로 저장됩니다. 다른 그림으로 이동할 때 현재 변경 내용을 먼저 저장합니다.

출력의 **문제 해결** 목록은 문항 번호와 자료 표지를 함께 표시합니다. 계획 내용이 빠졌으면 해당 그림 계획 입력으로, 계획이 저장됐지만 아직 확인 전이면 그 그림의 **제작 계획 확인** 단계로, 그림이 미확정이면 이미 저장된 그림의 편집 또는 최종 확인 단계로 이동합니다. 저장 완료 표시는 계획 확인이나 그림 최종 확정을 뜻하지 않습니다. 확인 버튼을 눌러야 다음 단계로 진행하며, 이미 만든 그림을 계획 확인 때문에 다시 생성하지 않습니다.

배경 생성 후 글씨 배치만 실패하면 편집 단계의 안내에서 **글씨만 자동 배치**로 재시도하세요. 저장된 배경을 다시 만들지 않습니다. 글씨가 필요 없으면 **글씨 없이 진행**을 선택합니다. 제작 계획을 수정해 승인이 해제되면 안내의 **문항 검토로 이동**으로 검토를 이어갈 수 있습니다. 그림이 없는 문항은 별도 안내를 표시하고, **다음 자료 그림**은 미확정 그림 문항으로 이동합니다.

1. **제작 계획**: 그림 유형·제작 규칙과 글씨 프롬프트를 검토합니다. 기존 카드라면 **기존 프롬프트를 그림·글씨로 분리**를 사용하세요. 문항카드 전체 승인 후 **제작 계획 확정 · 다음**을 누릅니다.
2. **그림 생성**: **그림 생성 시작**으로 글씨 없는 배경과 독립 글씨 객체를 생성합니다. 완료되면 편집 단계로 이동합니다. 업로드·기존 그림 선택은 **이미 준비한 그림이 있나요?**에 모았습니다. 글씨 생성에 실패해도 완료된 배경은 보존되며 편집 단계에서 글씨 프롬프트를 다시 적용할 수 있습니다.
3. **그림·글씨 편집**: 캔버스에서 도형과 글씨를 편집합니다. 상단 도구와 오른쪽 속성을 사용하며 **넓게 편집**도 가능합니다. 기본 도형·글씨 프롬프트 추가 적용·글씨 없이 완료는 접힌 설정 영역에 있습니다. **저장하고 최종 확인**으로 넘어갑니다. **배경 다시 만들기**로 돌아가 재생성해도 기존 글씨 객체는 유지됩니다.
4. **최종 확인**: 합성 미리보기에서 그림의 비례·방향과 글씨의 내용·위치를 확인하고 **그림 + 글씨 최종 확정**을 누릅니다. 확정 PNG를 내려받거나 **다음 자료 그림**으로 이동할 수 있습니다. 남은 그림이 없으면 검토·출력 단계로 이동합니다. 이후 그림이나 글씨를 수정하면 다시 확정해야 합니다.

배경과 글씨 객체는 편집 원본으로 따로 저장합니다. 최종 PNG는 3000×1920이며, 글씨가 경계 밖으로 잘리면 확정 전에 위치·크기 조정을 안내합니다. 기존 글씨가 박힌 그림의 글자를 자동으로 지우지는 않으므로 기존 배경은 글씨 없는 그림으로 교체하세요.

물리량·수식은 앱에 포함한 **Latin Modern Math** 원본 폰트로 렌더링합니다. 한글은 이 PC의 한글 프로그램에 설치된 **신명 중명조 HFT**를 별도 숨김 문서로 렌더링합니다. 열려 있는 사용자 문서에는 연결하지 않습니다. 다른 PC에서도 한글·해당 글꼴이 설치되어 있어야 하며, 사용할 수 없으면 다른 글꼴로 조용히 대체하지 않고 오류를 표시합니다. 글꼴 이름만 지정하는 방식이 아니라 화면과 최종 출력에 같은 글씨 렌더 결과를 사용합니다.

수식 렌더러: [Ziamath](https://ziamath.readthedocs.io/en/latest/usage.html). Latin Modern Math 배포처와 라이선스: [GUST](https://www.gust.org.pl/projects/e-foundry/lm-math/download), `app/fonts/latinmodern-math-1959/doc/GUST-FONT-LICENSE.txt`. 한글 글꼴 파일은 프로젝트에 복사하지 않습니다.

## 순서 변경과 작업실 삭제

문항 목록 행이나 왼쪽 문항 버튼을 끌어 놓아 순서를 바꿉니다. 설계 목록의 위·아래 버튼은 없고 ⠿ 손잡이로 끌 수 있습니다. 키보드는 손잡이에 초점을 두고 Space로 잡은 뒤 ↑/↓로 이동하고 Space로 놓습니다. Esc는 이동을 취소합니다. 문항의 내용·배점·그림·AI 요청은 함께 이동하며 번호는 1번부터 다시 매기고 저장합니다. 전체 문항카드 승인은 다시 필요합니다. 정답 번호는 크게 표시하며, 만들어진 자료 그림은 아이디어 옆에 작은 썸네일로 보입니다. 여러 그림은 각각 표시하고 확정본·편집본·원본 순으로 사용합니다. 썸네일을 클릭하거나 키보드로 실행하면 해당 그림이 큰 모달로 열립니다. 닫기·Esc·바깥 클릭으로 닫으며 원래 썸네일에 초점이 돌아옵니다. 이 미리보기는 문항 선택이나 검토 상태를 바꾸지 않습니다.

상단 **작업실 삭제**에서 해당 시험을 삭제할 수 있습니다. 생성 중에는 삭제할 수 없습니다. 삭제한 폴더는 `exams/_studio_trash/<ID>`로 이동하며 엑셀 원본은 유지합니다. 수동 복구하려면 앱을 종료한 뒤 해당 ID 폴더를 `exams/_studio`로 되돌립니다.

내보낸 문항카드 XLSX에는 U~AF열로 AI 생성 요청·그림 유형·영역·수정 요청·글씨 프롬프트·글씨 객체 JSON·배치 상태·계획 버전을 추가합니다. 기존 템플릿 파일은 변경하지 않으며 이 XLSX를 다시 가져오면 해당 설정도 유지됩니다.

## 문항 수와 100점 배점

미리 채워진 템플릿의 번호·배점만으로 문항 수를 판단하지 않습니다. 성취기준·아이디어·문항 내용이 실제 작성된 행을 읽습니다. 1~20번을 작성했다면 20문항만 가져오고 생성·출력합니다. 번호가 누락되거나 중복되면 조용히 번호를 바꾸지 않고 해당 위치를 안내합니다. 현재 지원 범위는 템플릿과 같은 1~100문항입니다.

배점은 AI 초안 생성 뒤 검토하면서 정합니다. 배점 패널에서 문항별 점수를 직접 입력하거나 **권장 배점 적용**을 눌러 하:중:상 1:1.25:1.5 상대 가중치 기준의 권장안을 적용할 수 있습니다. 권장안은 0.1점 단위로 반올림 잔여분을 분배해 합계가 100점이 되며, 자동으로 적용되지 않습니다. 점수는 비워 둘 수 있고, 입력할 때는 0 초과 100 이하로 지정합니다. 전체 문항 승인과 출력 전에는 합계 100점을 확인합니다.

## 검산과 승인 범위

자동 검사는 모든 물리적·교육적 타당성을 증명하지 않습니다. SymPy는 제공된 등식의 일치를 검사합니다. 변수는 양수로 해석하며, 부호가 변할 수 있는 양은 명시적 수치나 별도 변수를 사용해 조건을 분명히 해야 합니다. 검산식은 `이름 | lhs | rhs` 한 줄씩 입력합니다. 허용 연산은 `+ - * / ** sqrt sin cos tan Abs pi`입니다. 예: `이동 거리 | 2*3 | 6`.

그림 검사도 모델이 반환한 좌표 제약 등식을 검사하며 SVG의 모든 요소와 제약의 대응을 자동 증명하지 않습니다. 실제 그림의 수치·연결·라벨 확인이 필요합니다. 실패한 제약이 있으면 최종 확정에서 실제 결과를 보여줍니다. 취소해 수정하거나 **오류를 확인했고 그래도 승인**을 선택할 수 있습니다. 계산·그림 예외 승인은 현재 내용과 검사 결과에 묶여 저장되며, 관련 내용이 바뀌면 다시 확인해야 합니다. 검산식 누락, 그림·글씨 작업 누락, 제작 계획 미확인이나 그림 파일 변경은 해당 예외로 넘길 수 없습니다.

문항 내용·배점·순서가 바뀌면 전체 문항카드 승인이 해제됩니다. 본문·선택지·자료가 바뀌면 해당 그림 승인도 해제됩니다. 수정된 문항에 맞춰 그림을 다시 생성·업로드·선택해야 합니다. 이전 그림 파일과 출력 버전은 남아 있으므로 원본은 유실되지 않습니다. 내보낸 파일은 그 시점의 스냅샷이며 후속 수정은 새로 출력해야 반영됩니다.

화면 미리보기는 물리량·수식을 Latin Modern Math로 렌더링합니다. `$...$`, `$$...$$`, `\(...\)`, `\[...\]`와 구분자가 없는 `V_0`, `v_y` 같은 첨자 기호를 지원합니다. 카드의 수식은 LaTeX로 작성하고 각 첨자는 `$P_{0} V_{0}$`처럼 중괄호로 구분합니다. HML에는 같은 내용을 역슬래시 없는 한글 `EQUATION` 개체로 변환해 넣고, 항 전체와 첨자 범위를 별도로 묶습니다. 지원하지 않는 수식 명령은 손상된 결과를 내보내는 대신 해당 표기를 안내합니다. 일반 파일명·URL은 수식으로 바꾸지 않습니다. 앱은 HML의 XML·표 구조·그림 바이트·수식 보존을 검사하지만 한글의 전체 시험 페이지 렌더링까지 검증 완료라고 표시하지 않습니다. 예전에 만든 출력 파일은 보존되므로 변환기 수정 내용을 반영하려면 시험지를 다시 생성해야 합니다.

과거 카드의 `객관식`은 발문·보기 구조에 따라 네 가지 유형으로 임시 대응하며 검토 메모에 남깁니다. 이전 이름인 `단일 정답형`과 `단일정답형`은 `최선답형`으로 정규화합니다. 과거 회차의 해설이 별도 Markdown에만 있다면 앱의 해설 칸에 입력하거나 CLI로 생성해야 합니다. 빈 템플릿에 미리 기입된 번호·배점만 있는 행은 실제 문항으로 가져오지 않습니다.

## 자료 그림 객체 편집

자료 그림에서 **그림을 편집 객체로 변환**을 누르면 생성된 SVG의 선·도형을 분리합니다. 기존 물리량·수식·한글 객체는 그대로 유지됩니다. PNG/JPG는 흑백 윤곽선으로 추적합니다. 색과 질감은 보존하지 않으며 맞닿은 요소는 하나로 묶일 수 있습니다. 윤곽 기준을 높이면 옅은 선까지 포함합니다.

- 객체를 선택하여 이동하고 파란 손잡이로 너비·높이를 각각 조절합니다. 위쪽 둥근 손잡이로 회전합니다. 비율 유지 또는 Shift를 사용하면 비율을 고정합니다.
- 아래 속성에서 위치·너비·높이, 상대 회전 각도, 선 두께·색·점선·채움을 입력합니다. 선 객체는 길이도 수치로 입력할 수 있습니다. 좌표와 길이는 1000 × 640 캔버스의 단위이며 cm나 물리적 길이가 아닙니다.
- 노란 점은 선 끝점과 경로의 꼭짓점, 보라 점은 곡선 조절점입니다. 각각 끌어서 형태를 변경합니다. 매우 복잡한 경로는 개별 조절점 대신 전체 크기·회전 편집을 지원합니다.
- 선·화살표·사각형·타원·꺾은선·곡선을 추가할 수 있습니다. 복제·삭제, 앞뒤 순서, 좌우·상하 반전, 표시·숨김, 잠금·해제를 지원합니다.
- **자료 디자인 상단 도구 모음**에서 복사·붙여넣기·복제·삭제, 맨 앞으로·맨 뒤로, 묶기·풀기, 반전·회전을 사용합니다. 아이콘 옆에 기능 이름이 표시되고 마우스를 올리면 설명이 보입니다. **정렬·간격**을 펼치면 정렬 버튼이 나타납니다. 오른쪽 속성 영역에서는 위치·크기·스타일·글씨 내용을 편집합니다.
- Shift+클릭으로 여러 객체를 선택해 정렬하거나 묶고, 묶음을 다시 풀 수 있습니다. 겹쳐 선택하기 어려운 객체와 숨긴 객체는 캔버스 아래 객체 목록에서 선택합니다.
- 방향키로 1칸, Shift+방향키로 10칸 이동합니다. Delete는 선택 그림 삭제, Ctrl+D는 복제, Ctrl+Z / Ctrl+Y는 그림 편집 취소·다시 실행입니다. 단축키는 캔버스에 초점이 있을 때 적용됩니다. (가), (나) 각 그림의 선택·도구 설정·실행 취소 이력은 그림을 전환해도 따로 이어집니다. 페이지를 새로고침하면 실행 취소 이력은 초기화되지만, 저장한 그림과 글씨 위치는 유지됩니다.
- **넓게 편집**을 누르면 자료 디자인이 화면 전체를 채우고 창 크기에 맞춰 캔버스가 조절됩니다. **축소** 버튼이나 Esc로 원래 화면에 돌아옵니다. 전체 화면에서도 아래쪽 저장·확정 버튼을 사용할 수 있으며, 확대율·격자·10칸 맞춤을 지원합니다.
- **그림·글씨 편집 저장**으로 객체와 편집 SVG·PNG를 저장합니다. 앱을 다시 열어도 객체 편집을 이어갈 수 있습니다. 원본 PNG와 저장된 편집 SVG를 내려받을 수 있습니다.
- **원본 그림으로 복원**은 그림 객체 편집을 되돌리고 글씨는 유지합니다. 같은 편집 세션에서는 실행 취소로 복원 전 상태를 다시 가져올 수 있습니다. 실행 취소 이력은 현재 문항·원본별 최근 60단계이며 새로고침하면 초기화됩니다.
- 객체 편집은 문항카드 승인을 유지하고 그림 최종 확정을 해제합니다. 생성 당시 좌표 검산은 편집 후 도형의 비례를 검증하지 않으므로 직접 확인한 뒤 **그림 + 글씨 최종 확정**을 누릅니다. 최종 이미지가 시험지에 들어갑니다.
- 배경을 AI로 재생성하거나 새 그림을 업로드하면 그림 객체는 새 원본으로 교체되고 글씨 객체는 유지됩니다. 새 그림에서 다시 객체 변환을 실행하세요. 원본·저장 시점의 SVG/PNG 파일은 assets에 남습니다.

## 지도 자료

위치가 문제의 핵심인 사회·과학 문항에는 지도를 넣을 수 있다. 지도는 AI가 그리지 않고 앱이 실제 지형 자료로 그린다. 현대 지도는 Natural Earth(퍼블릭 도메인), 남한 시·도와 시·군·구는 통계청 SGIS 경계(공공누리 제1유형, vuski/admdongkor 가공 CC BY 4.0), 과거 국가 영역은 Cliopatria(CC BY 4.0), 지질시대 대륙과 판 회전은 PaleoMAP(CC BY 4.0)를 쓴다. 출처와 바꾼 점은 `app/map_data/출처.md`에 있다.

1. 문항의 자료 요청에서 **그림**을 고르고 유형을 **strict**로 두고, 요청 칸에 "지도로 도시 세 곳의 위치를 A, B, C로 표시" 처럼 적는다.
2. AI가 "SVG 규칙" 칸에 `지도:`로 시작하는 명세를 쓴다. 그 칸 아래 **지도 편집** 화면에서 표시 위치와 범위를 확인한다.
3. 그림을 생성하면 지도가 그려지고 글씨는 글씨 레이어로 들어가 위치를 옮길 수 있다.

사회·과학 과목의 그림 계획에는 **실제 지도로 그리기** 버튼이 있다. AI 없이 교사가 바로 지도를 시작할 때 쓴다. 누르면 그림 유형이 strict로 바뀌고 빈 세계 지도가 열린다.

### 지도 편집 화면

- **시대**: 현대, 역사·연도, 지질시대 중 하나를 고른다. 시대를 바꾸면 그 시대에 쓸 수 없는 음영만 빠지고 점·영역·경로는 남는다.
  - **역사·연도**: 연도를 적는다(기원전은 `-500`처럼 음수). "그해 국경 모두"를 켜면 그해 나라들의 경계가 그려진다. 나라·시도 음영 대신 **그해 나라**를 한국어 이름으로 골라 칠한다. 이름이 괄호로 싸인 것(예: 대영제국 전체)은 속한 나라를 모두 합친 범위다. 현대 국경·시·도 경계는 함께 쓰지 않는다.
  - **지질시대**: 시기(예: 250Ma · 트라이아스기)와 바탕(대륙붕까지 포함한 대륙 / 당시 해안선)을 고른다. 범위는 지구 전체로 바뀐다. 좌표는 그 시기의 경위도다. 판게아는 250Ma 안팎이다.
    - 표시를 고르고 **지금 위치로 적기**를 켜면 경위도를 지금의 위치(예: 서울 127, 37.5)로 적는다. 앱이 판 회전 모형으로 그 시기의 위치를 계산해 그린다. 손잡이를 끌어도 지금 좌표로 저장된다. 그 시기에 아직 없던 땅(어린 화산섬 등)은 오류로 알려 준다.
- **지도 범위**: 이름으로 고르거나 "경위도로 직접"을 골라 서·남·동·북 경위도를 적는다. 현대 국경, **시·군·구 경계**, 큰 강, 육지 흰색, 축척 막대(km)를 켜고 끈다. 한반도·남한 범위를 이름으로 고르거나 시·군·구를 쓰면 시·도 경계가 그려진다. 시·군·구 경계는 경위도로 직접 정한 좁은 범위(예: 수도권)에서도 쓸 수 있다.
- **표시 추가**: 점, 번지는 음영, 나라·지역 음영, 영역, 경로, 점선 위선·경선, 말풍선을 더한다. 표시 글씨는 A, (가), ❶ 순서로 비어 있는 것이 자동으로 붙는다.
- **옮기기**: 지도 위 파란 손잡이를 끌면 위치가 옮겨진다. 손잡이를 고른 뒤 방향키로 0.1°씩, Shift+방향키로 1°씩 옮길 수 있다.
- **경로·영역**: 목록에서 고른 뒤 지도의 빈 곳을 누르면 꼭짓점이 끝에 이어진다. 꼭짓점 손잡이를 고르고 "고른 꼭짓점 삭제"로 뺀다.
- **나라·지역 음영**: 칠할 단위(나라 / 시·도 / 시·군·구)를 고른 뒤 이름을 더한다. 나라는 한국어 이름으로 고른다. 칠하기는 회색, 진한 회색, 빗금, 흰색 중 하나다.
- **말풍선**: 글을 적고 꼬리가 가리킬 위치(손잡이)를 끌어 옮긴다. 상자 위치는 비워 두면 앱이 정하고, 가로·세로 화면 거리로 정할 수도 있다. 글은 줄바꿈으로 여러 줄이 된다.
- 편집하면 명세가 "SVG 규칙" 칸에 바로 다시 적히고 저장된다. 그림 계획을 고친 것이므로 문항카드 승인과 제작 계획 확인을 다시 받는다. JSON을 칸에 직접 고쳐도 편집 화면이 따라 바뀐다.
- 미리보기의 글씨는 위치 확인용이다. 시험지 글꼴로 된 글씨는 그림 생성 뒤 글씨 레이어에서 보고 옮긴다.
- 문항카드를 승인한 뒤 그림 단계에서는 지도를 읽기 전용으로 보여 준다. 고치려면 "계획 수정"을 누른다.

명세의 항목은 다음과 같다. 예: `지도: {"view":"mediterranean","points":[{"at":[14.3,40.8],"label":"A"}]}`

| 항목 | 뜻 |
|---|---|
| `view` | `world`, `east_asia`, `korea`, `south_korea`, `japan`, `china`, `southeast_asia`, `south_asia`, `central_asia`, `silk_road`, `middle_east`, `mediterranean`, `europe`, `africa`, `north_america`, `south_america`, `oceania`, `atlantic`, `indian_ocean`, `pacific`, 또는 `[서, 남, 동, 북]` 경위도 |
| `points` | 점. `at`은 `[경도, 위도]`, `label`은 A 같은 표시, `side`는 글자 방향, `open`이 참이면 빈 원 |
| `shade` | 현대 나라(`countries`, ISO 세 글자), 한국 시·도(`provinces`), 남한 시·군·구(`districts`, 예: `강원특별자치도 춘천시` 또는 겹치지 않는 `춘천시`) 음영. `pattern`은 `gray`, `dark`, `hatch`, `white` |
| `districts` | `true`이면 남한 시·군·구 경계를 그린다 |
| `callouts` | 말풍선. `at`은 꼬리가 가리킬 `[경도, 위도]`, `text`는 글(줄바꿈 `\n`), `offset`은 상자까지의 화면 거리 `[가로, 세로]`(생략 가능) |
| `areas` | 과거 영토처럼 현대 국경과 다른 범위의 다각형 |
| `blobs` | 경계를 확정할 수 없는 지역의 번지는 음영. `radius`는 `[경도 폭, 위도 폭]` |
| `routes` | 원정로·교역로. `path`, `label`(❶ 등), `dash`, `arrow` |
| `lines` | 점선 위선(`lat`)이나 경선(`lon`) |
| `borders`, `rivers`, `land`, `scale_km` | 현대 국경, 큰 강, 육지를 희게(`white`), 축척 막대 |
| `year`, `past_borders` | 역사 지도의 연도(-3400~2024, 기원전은 음수)와 그해 국경 모두 표시 |
| `shade`의 `polities` | 그해 나라의 영어 이름이나 한국어 이름. 예: `{"polities":["고구려"],"label":"(가)"}` |
| `ma`, `paleo` | 지질시대(백만 년 전, 0~535)와 바탕(`margin` 대륙붕 포함 대륙, `coast` 당시 해안선). `view`는 `globe` |
| 표시의 `present` | 지질시대 지도에서 `true`이면 그 표시의 좌표를 지금 위치로 읽고 그 시기 위치로 옮겨 그린다 |

역사 지도에는 `borders`를 쓰지 않는다. 표시한 곳이 지도 범위 밖이면 오류로 알려 준다. 해안선 자료는 정확하지만 시대별 위치와 범위는 AI가 적은 값이므로 교사가 확인한다.

과거 국가 영역 자료는 하나의 견해다. 특히 고조선·고구려·한사군처럼 견해가 갈리는 고대 한국사·동아시아사 영역은 교과서와 다를 수 있으므로, 평가원처럼 번지는 음영(`blobs`)이나 직접 그린 영역을 쓰고 자료 영역은 교과서와 대조한 뒤에만 쓴다. 과거 국경의 해안 쪽은 자료가 거칠어, 앱이 영역을 칠한 뒤 바다를 덮어 현대 해안선 안쪽만 남긴다.

남한 시·도와 시·군·구는 2026년 10월 행정 구역이다. 전라남도와 광주광역시는 전남광주통합특별시 하나로 그려지며, 통합 전 이름으로 칠하면 옛 범위를 칠한다. 시·군·구 이름이 겹치면(중구, 동구, 고성군 등) 시·도를 붙여 쓴다.

학교 밖에 공개하는 시험지에 과거 국경, 지질시대 지도, 시·군·구 지도를 쓰면 출처를 적는다. 예: "지도 자료: Cliopatria (CC BY 4.0)", "행정 경계: 통계청 SGIS(공공누리 제1유형)".

## 도식 자료 (생명과학·화학)

가계도처럼 수와 관계가 정확해야 하는 그림은 AI가 그리지 않고 앱이 명세대로 그린다(2026-11-04). 과학 과목의 AI 초안에서 그림을 요청하면 AI가 "SVG 규칙" 칸에 `도식:`으로 시작하는 명세를 쓴다. 칸의 JSON을 직접 고쳐도 된다. 그림 유형은 strict이고, 번호·기호·원소 기호·이름표는 글씨 레이어로 들어가 옮길 수 있다.

| 종류(`type`) | 쓰임 | 명세의 핵심 |
|---|---|---|
| `pedigree` 가계도 | 유전 형질 추론 | `generations` 세대별 번호, `people` 성별(M/F)·형질(`a`, `b`, `ab`)·보인자, `couples`, `children`. 범례는 앱이 만든다 |
| `foodweb` 먹이 그물 | 생태계 | `levels` 생산자부터 단계별 이름, `links` 먹히는 쪽 → 먹는 쪽 |
| `pyramid` 생태 피라미드 | 에너지·개체 수 | `levels` 아래부터 이름과 값(폭이 값에 비례) |
| `sequence` 염기 서열 | DNA·RNA·코돈 | `strands` 가닥별 서열(15염기 이하)·끝 표시(5′, 3′)·코돈 묶음·표시 ㉠, `pairs` 상보 가닥 |
| `cell` 세포 소기관 | 세포 구조 | `kind` 동물·식물, `marks` 소기관과 A~E |
| `particles` 반응 입자 모형 | 화학 반응·양적 관계 | `panels` 반응 전·후 칸마다 분자(원자 목록)와 개수. 원소 4종류까지, 범례는 앱이 만든다 |
| `energy` 반응 경로-에너지 | 반응열·활성화 에너지·촉매 | `reactant`, `product`, `peak`, `catalyst`(점선), `marks` 두 높이의 차이 (가)(나) |

코돈표처럼 큰 표는 그림이 아니라 표 자료로 넣는다. 명세의 수(구성원, 분자 수, 염기 수)가 문항 조건과 맞는지는 교사가 확인한다.
