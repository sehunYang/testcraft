# HWPML 문항지 생성 지침

> 완성된 문항 카드(엑셀)를 **학교 양식 그대로의 한글 문항지(.hml)** 로 변환하는 절차.
> 이 문서 하나로 처음부터 재현할 수 있도록 시행착오와 함정까지 기록한다.

---

## 0. 결론부터 — 반드시 이 경로로 갈 것

```
문항 카드(.xlsx)  →  tools/gen.py  →  .hml  →  한글에서 열기
                                          →  tools/수식크기_재계산.py 실행  →  완성
```

**docx 경로는 쓰지 말 것.** 검증 결과 **한글은 docx의 표준 수식(OMML)을 읽지 못하고 수식 자리가 통째로 비어 보인다.** LibreOffice와 한글 모두에서 확인했다. 문자식(√, π, 첨자)으로 낮춰 넣으면 보이기는 하나 세로 분수를 쓸 수 없다.

## 1. 준비물

| 파일 | 역할 |
|---|---|
| `input/item-ideas/*.xlsx` | 문항 카드 (문두·자료·발문·보기·답지·정답·배점) |
| `templates/학교양식_예시.hml` | **학교 양식 원본.** 글꼴·문단·표 양식의 유일한 출처 |
| `tools/gen.py` | 카드 → .hml 생성기 |
| `tools/metrics.py` | 수식 폭·높이·기준선 추정 |
| `tools/수식크기_재계산.py` | 한글 COM으로 수식 크기 재계산 (마무리) |

**양식 예시 파일이 없으면 시작하지 말 것.** 서식을 추측으로 만들면 반드시 어긋난다.

## 2. 핵심 원칙 — 양식은 만들지 말고 빌려 쓴다

`gen.py`는 양식 예시 파일에서 다음을 **그대로 가져다 쓴다.**

- `<HEAD>` 전체 (글꼴 7언어, 문자모양, 문단모양, 테두리, 용지) — 통째로 재사용
- `<SECDEF>` (용지·여백 정의) — 첫 문단에 복사
- 표 양식 8종 — `copy.deepcopy` 후 칸 내용만 교체

```python
HEAD  = TPL[TPL.index('<HEAD '):TPL.index('</HEAD>')+7]
SK = {'짧은': TP[26].find('.//TABLE'), '중간': TP[28].find('.//TABLE'), ...}
```

양식 파일의 문단 번호(26, 28, 30…)는 **그 파일 구조에 종속**된다. 새 양식 파일을 받으면 문단 번호부터 다시 확인할 것.

### 문자모양·문단모양 매핑 (현재 양식 기준)

| 용도 | 값 |
|---|---|
| 문항 번호 | CharShape **3** (13pt) |
| 본문 | CharShape **1** (11pt 한양신명조) |
| 문항 문단 | ParaShape **2** (첫줄 내어쓰기) |
| 일반 문단 | ParaShape **1** |

## 3. 수식 — 가장 많은 시행착오가 있었던 부분

### 3.1 반드시 지킬 구조

```xml
<EQUATION BaseLine="85" BaseUnit="1100" LineMode="false" TextColor="0" Version="Equation Version 60">
  <SHAPEOBJECT InstId="고유값" ...>        ← 이 래퍼가 없으면 '글자처럼 취급'이 안 먹는다
    <SIZE Width="…" Height="…" .../>
    <POSITION TreatAsChar="true" VertAlign="Top" .../>
    <OUTSIDEMARGIN Left="0" Right="0" Top="0" Bottom="0"/>
  </SHAPEOBJECT>
  <SCRIPT>{sqrt {3}+1} over {4} mg</SCRIPT>
</EQUATION>
```

**함정 1 — `SIZE`/`POSITION`을 `<EQUATION>` 바로 아래 두면** 한글이 무시하고 '어울림'으로 처리한다. 반드시 `<SHAPEOBJECT>` 안에 넣는다.

**함정 2 — `InstId`가 중복되면 파일이 열리지 않는다.** 개체마다 고유값을 부여할 것. (이것 때문에 시험 파일이 한 번 깨졌다.)

**함정 3 — `LineMode`는 `"false"`**, `"0"`이 아니다.

### 3.2 `BaseLine` — 세로 위치를 결정하는 값

**상자 위에서 baseline까지의 비율(%)** 이다. 이 값이 없으면 한글이 상자 바닥을 baseline에 붙여 **수식이 위로 떠오른다.**

양식 예시 파일에서 한글이 직접 계산한 값:

| 내용 | Height | BaseLine | ascent |
|---|---|---|---|
| 평범 | 1125 | 85 | 956 |
| 아래첨자 | 1350 | 71 | 958 |
| `vec` 포함 | 1575 | 75 | 1181 |

**ascent가 956으로 일정**한 것이 핵심. 나머지는 이 규칙에서 추정한다(`metrics.py`).

### 3.3 LaTeX → 한글 수식 스크립트

| LaTeX | 한글 스크립트 |
|---|---|
| `\dfrac{a}{b}` | `{a} over {b}` |
| `\sqrt{3}` | `sqrt {3}` |
| `\sqrt[3]{x}` | `root { 3 } of { x }` |
| `\text{km/s}` | `rm {km/s}` (단위는 정체) |
| `\vec{F}_1` | `{ { vec { F } } _ { 1 } }` |
| `30^\circ` | `{ 30 ^ { circ } }` |
| `\sim` | `SIM` |
| `\pm`, `\mp` | `PLUSMINUS`, `MINUSPLUS` |
| `\parallel` | `VERT` |
| `\ldots`, `\cdots` | `LDOTS`, `cdots` |
| `->` | 화살표 한 글자로 렌더된다 (폭 계산 시 주의) |

변환기는 한컴 수식 문법으로 구조를 해석해 내보낸다. 특히 아래첨자는 매 변수마다
`{ P _ { 0 } } { V _ { 0 } }`처럼 항 범위를 중괄호로 고정하므로 다음 변수가 앞 변수의
첨자에 붙지 않는다. 지원하지 않는 LaTeX 명령은 오류로 중단하며, 원문 역슬래시를 SCRIPT에
남기지 않는다.

**물결표 문자와 수식 간격 명령은 구분한다.** 카드의 일반 문장·표 셀이나 수식에 입력한
ASCII `~`는 HML에서 유니코드 `∼`로 출력한다. 원본 카드와 저장된 엑셀은 바꾸지 않는다.
`\sim`은 한컴 수식의 native `SIM`으로 출력하고, `\~`는 악센트가 아닌 문자 `∼`로
허용한다. `\quad`, `\qquad`, `\;`, `\:`은 한컴 간격 표식으로 변환되므로 물결표 문자로
바꾸지 않는다.

`V_12`처럼 변수 뒤의 연속 숫자는 한 숫자 첨자로 묶어 보존한다. 둘 이상의 문자나 식 전체를
첨자로 지정할 때는 LaTeX처럼 `V_{net}` 또는 `V_{i+1}`로 중괄호를 쓴다. 이미 한글 수식
명령어로 적힌 `rm`, `DELTA`, `over` 같은 이름도 native 명령어로 인식한다.

문법 기준은 한컴 공식 문서 [한글 문서 파일 형식 - 수식, revision 1.3](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_%EC%88%98%EC%8B%9D_revision1.3.pdf)이다. 이 문서는 `{}`를 여러 항의 묶음, `_`/`^`를 아래·위첨자, `OVER`와 `SQRT`를 분수·제곱근 명령으로 정의한다.

**근 지수 표기는 공식 예시와 설치 엔진을 구분한다.** revision 1.3 §2.3에는 `^3sqrt{x}` 예시가 있지만, 현재 설치된 한글에서는 이 표기와 첨자 중괄호 변형들이 식 전체를 비워 둔다. 독립 HML fixture에서 렌더링을 확인한 `root { 3 } of { x }` 형식으로 변환한다.

### 3.4 크기는 결국 한글에게 맡긴다 ★

`metrics.py`가 아무리 정확해도 **±15% 오차가 남는다.** 좁으면 글자가 겹치고 넓으면 빈틈이 생기며, 분수는 위아래가 잘린다.

**근본 해결은 `tools/수식크기_재계산.py`다.** `pyhwpx`(한글 COM)로 수식 개체의 속성을 한글에 되돌려주면 한글이 수식을 다시 그리면서 폭·높이·기준선을 스스로 계산한다.

```python
pset = ctrl.Properties
pset.SetItem("String", pset.Item("String"))
ctrl.Properties = pset          # ← 이 대입이 재계산을 일으킨다
```

`.hml`을 만든 뒤 **반드시 이 스크립트를 한 번 돌린다.** 그러면 `metrics.py`의 오차는 무의미해진다.

> 시도했다가 실패한 방법: `Width="0"`/`"1"`로 저장해 한글이 계산하게 하기 → 깨져서 열린다.

## 4. 표 처리

### 4.1 답지 표는 폭을 재서 자동 선택

| 양식 | 내용 칸 폭 | 조건 |
|---|---|---|
| 짧은 것 (1×11) | 4728 | 최대 폭 ≤ 3700 **이고 분수 없음** |
| 중간 (2×7) | 9536 | 최대 폭 ≤ 7200 |
| 긴 것 (5×3) | 29742 | 그 외 |
| 짝짓기 2개 (4×8) | — | (가)/(나) 2열 답지 |
| 짝짓기 3개 (4×10) | — | (ㄱ)/(ㄴ)/(ㄷ) 3열 답지 |

**분수가 든 답지는 폭이 좁아도 '중간' 이상**을 쓴다. 분수는 세로로 커서 짧은 표에서 잘린다.

### 4.2 칸 내용 교체 시 문자모양 함정 ★

템플릿 칸의 **첫 TEXT가 들여쓰기용 작은 글자**인 경우가 있다(지문 박스는 9pt 공백 두 칸 + 11pt 본문). 첫 TEXT의 문자모양을 그대로 쓰면 **본문이 9pt로 깨진다.**

```python
main = next((t for t in ts if (t.findtext('CHAR') or '').strip()), None) or ts[0]
cs = main.get('CharShape')      # 내용이 있는 TEXT 의 문자모양을 쓸 것
```

### 4.3 셀 세로 정렬

생성 마지막에 모든 셀의 `<PARALIST VertAlign>`을 `Top`으로 일괄 변경한다.

## 4.5 표의 칸 구조는 절대 새로 짜지 않는다 ★ (2026-09-09 사고)

〈보기〉를 한 줄에 3개씩 넣으려고 양식 표에 열을 추가했다가 **한글이 파일을 열지 못했다.**
HWPML 표는 다음이 모두 맞아야 한다.

- `ColCount` = **모든 행**에서 (그 행의 `ColSpan` 합 + 위에서 `RowSpan`으로 내려온 칸의 `ColSpan` 합)
- `RowCount` = `ROW` 개수, 각 `CELL`의 `RowAddr` = 그 행 번호
- 행마다 `Width` 합이 같아야 한다

양식 표는 세로 병합(`RowSpan`)을 쓰고 있어서 한 행만 고쳐도 다른 행과 어긋난다.
**해결: 칸 구조는 양식 그대로 두고 칸 안의 글자만 바꾼다.**
한 줄에 여러 항목을 넣어야 하면 칸을 쪼개지 말고 **한 칸 안에 공백으로 이어 붙인다**
(`ㄱ. 시간    ㄴ. 변위    ㄷ. 질량`).

`gen.py`는 저장 직전에 위 세 조건을 검사하고, 어긋나면 **저장하지 않고 중단**한다.
"표 구조 검증 통과: N개"가 찍히지 않으면 파일을 전달하지 말 것.

## 5. 정답 형광펜 ★ (2026-09-14 수정)

- **번호 칸(①②③④⑤)** 에 칠한다. 내용 칸이 아니다.
- **반드시 한글의 '형광펜'(`MARKPEN`)을 쓴다. 글자 음영(`ShadeColor`)을 쓰지 않는다.**

### 왜 형광펜이어야 하는가

| | 화면 | 인쇄 |
|---|---|---|
| 형광펜 `MARKPEN` | 보인다 | **찍히지 않는다** |
| 글자 음영 `CHARSHAPE ShadeColor` | 보인다 | **그대로 찍힌다** |

형광펜은 인쇄되지 않으므로 **정답이 칠해진 교사용 파일을 그대로 출력해도 학생용이 된다.**
음영을 쓰면 출력할 때마다 색을 지워야 하고, 지우는 것을 잊으면 정답이 인쇄된 시험지가 나간다.
실제로 그런 일이 있었다.

### 쓰는 법

`<CHAR>` 안에서 글자를 `MARKPENBEGIN` / `MARKPENEND` 로 감싼다.

```xml
<TEXT CharShape="1"><CHAR><MARKPENBEGIN Color="65535"/>③<MARKPENEND/></CHAR></TEXT>
```

```python
HL_COLOR = '65535'                       # 노랑 (0x00FFFF, BGR)

def markpen(text_el, color=HL_COLOR):
    for ch in text_el.iter('CHAR'):
        txt = ch.text or ''
        if not txt.strip(): continue
        ch.text = None
        b = ET.SubElement(ch, 'MARKPENBEGIN', {'Color': color})
        b.tail = txt                      # 글자는 BEGIN 의 tail 로 들어간다
        ET.SubElement(ch, 'MARKPENEND')
```

`tail` 에 넣는 것이 핵심이다. `ch.text` 에 그대로 두면 글자가 형광펜 구간 **밖**에 남는다.

### 덤으로 얻는 것

형광펜 방식은 `HEAD`(`CHARSHAPELIST`)를 전혀 건드리지 않는다. 예전 음영 방식은 문자모양을
복제해 추가해야 했고, 그 과정에서 정규식이 `Id="1"` 대신 `BorderFillId="1"` 에 걸려
글꼴·크기가 초기화되는 사고가 있었다. **그 함정 자체가 사라졌다.**

### 검증

생성 후 `<MARKPENBEGIN` 개수가 문항 수와 같은지, 칠해진 번호가 문항 카드의 답과
일치하는지 확인한다. `gen.py` 가 `형광펜 N` 으로 찍어 준다.

### 이미 음영으로 칠해진 파일을 고칠 때

노란 음영을 흰색으로 바꾸면 인쇄에서 사라진다. 두 곳을 모두 봐야 한다.

```python
raw = re.sub(r'(<MARKPENBEGIN Color=")65535(")', r'\g<1>16777215\g<2>', raw)
raw = re.sub(r'<CHARSHAPE[^>]*ShadeColor="65535"[^>]*>',
             lambda m: m.group(0).replace('ShadeColor="65535"',
                                          'ShadeColor="16777215"'), raw)
```

## 6. 그림 프롬프트 구분

그림 자료는 나중에 이미지 생성 도구에 넘겨야 하므로 경계를 명확히 한다.

```
〔그림 프롬프트 시작 · 14번〕
지면 위에 사람이 서 있고 …
〔그림 프롬프트 끝 · 14번〕
```

- **`〔자료〕` 표기는 쓰지 않는다.** 표·지문 박스로 들어간 자료에도 남아 파싱 근거가 될 수 없다.
- 표 자료 → 데이터 표, 글상자 자료 → 지문 박스로 들어가며 아무 표기도 붙이지 않는다.
- 마커에 문항 번호를 넣어 이미지와 문항을 대응시킨다.

## 7. 실행

```bash
cd <작업 폴더>
python3 tools/gen.py                    # 문항카드.xlsx → 문항지_양식.hml
```

`gen.py` 상단에서 다음을 확인·수정한다.

- `TPL` — 양식 예시 파일 경로
- `SK` — 표 양식이 있는 문단 번호
- `build(src=...)` — 문항 카드 파일명

생성 후 한글에서 열고 `tools/수식크기_재계산.py` 실행.

## 8. 생성 후 자동 검증 항목

| 항목 | 기준 |
|---|---|
| XML 적합성 | `ET.fromstring` 통과 |

| `〔자료〕` 잔여 | 0 |
| 그림 프롬프트 | 시작 개수 = 끝 개수 |
| 지문 박스 본문 | 문자모양 = 본문(11pt) |

## 부록 — 걸어본 길과 결과

| 시도 | 결과 |

| docx + OMML 표준 수식 | **실패.** 한글에서 수식 자리가 빈칸 |
