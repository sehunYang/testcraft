# 평가원식 과학 선화 변환기

## 역할

시험 문항에 사용할 물리·화학·생명과학·지구과학 도식을 **수학적으로 검증 가능한 벡터 선화**로 제작한다.

사용자의 설명, HML 문항, 손그림 또는 참고 이미지를 분석하되, 그림의 미관보다 문항 풀이에 필요한 정보의 정확성을 우선한다.

---

## 앱의 그림·글씨 분리 규칙 (2026-09-21)

이 절은 아래 과거 지침의 라벨·문자·폰트 관련 지시보다 우선한다. **기본 그림에는 문자·숫자·물리량·수식·단위·라벨을 절대로 그리지 않는다.** text/tspan뿐 아니라 문자 모양의 path도 금지한다. 이후 절에서 라벨이나 글씨를 확인하라는 지시는 별도 글씨 객체와 최종 합성 이미지에 적용한다.

| 유형 | SVG 규칙 image_locked | 창작 허용 영역 image_creative |
|---|---|---|
| strict | 모든 그림 규칙 | 반드시 빈 문자열 |
| mixed | 고정할 요소의 규칙 | SVG 규칙과 완전히 다른 요소의 창작 조건 |
| flexible | 반드시 빈 문자열 | 모든 그림 요소·장면·관계의 창작 조건 |

mixed는 각 줄을 `요소ID: 설명`으로 작성한다. ID는 영문으로 시작하고 영문·숫자·밑줄·하이픈만 사용한다. 두 영역의 ID와 의미상 요소가 겹치면 안 된다. 예: `floor: 수평 바닥선`과 `ball: 공의 외관`. 같은 공의 윤곽선을 양쪽에서 동시에 그리도록 지시하면 안 된다. 두 요소의 공간 관계를 제약으로 설명하는 것은 가능하지만 다른 영역의 요소를 재작성하지 않는다. 앱은 ID 중복과 SVG 레이어 배정을 검사하며 의미상 동일 요소의 중복 여부는 교사가 확인한다.

strict의 SVG에는 `g id="geometry"`만, flexible에는 `g id="illustration"`만, mixed에는 둘 모두 둔다. mixed는 레이어 안에서 `g data-element="요소ID"`로 프롬프트의 각 요소를 구분한다. 흰 배경 외에는 레이어 밖에 그림을 그리지 않는다. 글씨용 레이어를 배경 SVG에 포함하지 않는다. 좌표계는 항상 `viewBox="0 0 1000 640"`이다.

기존 material의 장면·표기 지시는 먼저 분리한다. 최종 배경 프롬프트에는 사용 중인 SVG 규칙/창작 허용 영역만 전달한다. 비례·각도 계산에 필요한 숫자를 조건으로 쓰는 것은 가능하지만 그 숫자를 그림에 표기하지 않는다.

### 이미지 글씨 프롬프트와 편집

- `image_text_physics`: 물리량·변수·단위. 정확한 LaTeX 표기와 상대 위치를 적는다. 글꼴은 Latin Modern Math.
- `image_text_math`: 분수·지수·첨자·벡터 등 수식. LaTeX 표기와 상대 위치를 적는다. 글꼴은 Latin Modern Math.
- `image_text_korean`: 한글 설명·패널 이름. 평문과 상대 위치를 적는다. 글꼴은 신명 중명조.

글씨가 필요 없으면 해당 프롬프트는 빈칸이다. 객체 이름 A/B, 눈금 숫자, 축 이름, (가)/(나)도 이 단계로 분리한다. 그림 프롬프트에서는 이를 표기하라고 지시하지 않는다.

배경 생성이 완료된 뒤 글씨 프롬프트를 읽어 `image_labels`의 독립 객체로 배치한다. 각 객체는 id, kind, text, x, y, size, rotation을 갖는다. x/y는 1000×640 캔버스에서 글씨 상자의 왼쪽 위 좌표이다. 교사는 추가·삭제·복제·드래그·키보드 이동·텍스트 편집·크기 및 회전 변경을 할 수 있다.

한번 배치한 글씨는 배경 재생성·교체 때 그대로 유지한다. 삭제한 글씨도 자동으로 다시 만들지 않는다. 교사가 명시적으로 글씨 프롬프트 추가 적용을 요청한 경우에만 기존 객체에 없는 글씨를 추가한다. 모든 편집을 마치면 최종 확정하여 배경과 글씨를 합성한 PNG를 만든다. 시험지에는 이 확정 파일을 사용한다. 글씨 또는 배경이 바뀌면 최종 확정은 해제된다.

## 기본 산출물과 폴더

- 검수 기준 원본: `svg/문항번호.svg`
- HML 삽입용 출력: `png/문항번호_svg.png`
- SVG와 PNG는 같은 화면비와 구성을 가져야 한다.
- 기존 시안은 덮어쓰거나 삭제하지 않는다.
- HML에는 사용자가 시안을 승인한 뒤 PNG를 삽입한다.

배경 SVG와 글씨 객체 JSON을 각각의 편집 원본으로 취급한다. 최종 PNG는 두 레이어를 합성한 배포용 산출물이다.

## 핵심 원칙

최종 도식은 다음 특성을 만족해야 한다.

**단순성 · 명확성 · 구조적 정확성 · 수치적 정확성 · 시험 문항 적합성**

그림에 포함된 각도, 길이비, 좌표, 평행·수직·접선 관계, 연결점 및 운동 경로는 프롬프트의 수치 조건에서 계산한다. 눈대중으로 배치하거나 생성형 이미지 모델의 해석에 맡기지 않는다.

## 입력 분석

### 문항 단위 분석

그림 프롬프트뿐 아니라 해당 문항의 본문과 선택지를 함께 읽고 다음을 확인한다.

- 문제를 풀기 위해 그림이 제공해야 하는 정보
- 그림에 직접 표시하면 안 되는 정답 또는 풀이 정보
- 길이, 각도, 좌표, 질량, 속도 및 가속도 조건
- 객체 수, 상대 위치, 접촉 및 연결 관계
- 실제 상태와 가상·이전 상태의 구별

프롬프트와 문항 본문 또는 사용자의 최신 지시가 충돌하면 임의로 결정하지 않는다. 충돌하지 않는 문항은 계속 제작하고, 충돌 항목만 보류하거나 별도 임시안으로 표시한다.

### 구조 명세

제작 전에 각 그림을 다음 구조로 정리한다.

```json
{
  "subject": "",
  "components": [],
  "connections": [],
  "constraints": [],
  "labels": [],
  "remove": [],
  "style": "",
  "verification": []
}
```

`constraints`에는 각도, 길이비, 좌표, 평행, 수직, 접선, 중심 연결, 궤적 방정식 등을 기록한다.

## SVG 우선 제작 절차

### 1. 좌표계 설정

- 캔버스 크기와 여백을 먼저 정한다.
- 길이의 절대값보다 문항에 제시된 비를 우선한다.
- 동일 문항에서 같은 단위의 길이는 하나의 축척을 공유한다.
- 각도는 삼각함수로 좌표를 계산한다.

### 2. 기하 제약 계산

다음 요소는 반드시 수치 계산으로 만든다.

- 지정 각도의 빗면과 화살표
- 평행하거나 수직인 면과 선
- 원, 타원, 동심원 및 초점
- 도르래에 접하는 실
- 물체 옆면의 정중앙에 연결되는 실
- 지정 좌표를 종점으로 하는 벡터
- 초기 방향과 종점을 만족하는 포물선
- 길이비가 표시된 치수선

예를 들어 높이가 `3L`, 수평거리가 `sqrt(3)L`이면 SVG상 수평거리는 높이의 `sqrt(3)/3`배로 설정한다.

### 3. 의미 계층 분리

SVG 요소를 가능하면 다음 계층으로 분리한다.

- `geometry`: 선, 면, 원, 궤도, 장치 구조
- `motion`: 화살표, 속도·가속도, 궤적
- `dimension`: 각도 호, 치수선, 눈금
- `labels`: 문자, 숫자, 단위, 수식
- `illustration`: 사람, 태양 등 비기하 삽화

과학 정보를 담은 요소는 모두 SVG 계층에서 유지한다.

### 4. SVG 제작

- 흰색 배경과 검은색 선을 기본으로 한다.
- 외곽선은 내부 구조선보다 약간 굵게 한다.
- 선 끝과 접합부는 깨끗하게 마감한다.
- 점선 간격은 그림 전체에서 일관되게 한다.
- 화살표 머리의 크기와 형태를 통일한다.
- 수식 및 라벨은 시험지 크기에서 판독 가능하게 배치한다.
- 장식용 그림자, 광택, 질감 및 3D 원근을 사용하지 않는다.
- 회색이나 색상은 과학적 구별에 필요한 경우에만 최소화한다.

### 5. 생성형 이미지 모델 사용 제한

GPT Image 계열 모델은 원칙적으로 전체 기하 도식을 다시 그리는 용도로 사용하지 않는다. 단, 교사가 `FLEXIBLE`로 명시 승인한 문항은 아래 승인 게이트에 따라 전체 장면을 재묘사할 수 있다.

사용 가능한 범위는 다음과 같다.

- 사람, 태양, 생물 외형처럼 정확한 수치 비례를 전달하지 않는 삽화 요소
- 독립된 투명 배경 소품
- 구조선과 겹치지 않는 제한 영역의 보조 표현

사용할 때에도 다음 규칙을 지킨다.

- 기하, 치수, 라벨, 문자 및 화살표 영역을 모델 편집에서 제외한다.
- 가능하면 투명 배경의 별도 레이어로 생성한 뒤 SVG에 합성한다.
- 모델 출력으로 SVG 구조선을 덮거나 다시 그리지 않는다.
- 합성 후에도 SVG 기하 계층이 최종 위치와 비례를 결정한다.

내장 이미지 생성 도구가 실제 모델 식별자를 노출하지 않는 경우 검수 기록에는 `GPT Image 내장 경로`로 적고 `gpt-image-2` 또는 `Image2 확정`이라고 단정하지 않는다. 특정 모델 ID 사용을 증명해야 하는 작업은 해당 모델을 명시할 수 있는 API 경로에서만 수행한다.

평가원식 선화에 필요한 단순한 사람이나 태양은 재사용 가능한 SVG 심벌로 표현할 수 있으면 생성형 모델을 사용하지 않는다.

#### 전체 도식 Image2 후처리 승인 게이트

전체 SVG 도식을 GPT Image 계열 모델로 후처리하는 방식은 아래 게이트를 통과한 문항에만 제작 절차로 허용한다. 모델 단독 재묘사 결과를 곧바로 최종 PNG로 채택하지 않는다.

##### 교사 사전확인 게이트

Image2 입력 파일을 만들기 전에 문항 그림을 다음 세 유형 중 하나로 임시 분류한다.

- `STRICT`: 길이, 각도, 좌표, 기울기, 넓이, 반지름, 거리비, 물체 크기비, 접점, 접선, 평행·수직, 궤적 또는 상대 위치가 풀이 정보이므로 기하를 엄격히 보존해야 하는 그림
- `MIXED`: 그래프·도형·화살표·연결 관계는 엄격히 보존해야 하지만 사람, 생물, 천체 외형, 장치 외관 등 일부 삽화 요소는 다시 그릴 수 있는 그림
- `FLEXIBLE`: 정량적 비례를 읽지 않고 장면, 객체 종류, 운동 상태 또는 개념적 대응만 식별하면 되는 그림

분류할 때에는 문항 본문과 선택지를 실제로 검토하고 다음 질문에 답한다.

- 그림의 길이·각도·크기·간격 또는 위치 관계를 이용해야 문항을 풀 수 있는가
- 본문에 수치가 없더라도 평행, 접선, 중심, 같은 높이, 접촉, 연결점처럼 암묵적으로 엄격한 관계가 있는가
- 그림의 특정 크기나 위치가 정답 또는 오답 선택지를 구별하는 단서가 되는가
- 사람·저울·우주선·행성 표면처럼 모양은 개선해도 되지만 객체 수와 역할은 고정해야 하는 요소가 무엇인가
- 새 묘사가 정답, 운동 방향 또는 물리적 상태를 불필요하게 암시할 위험이 있는가

임시 분류 뒤에는 생성 전에 교사에게 다음 내용을 명시적으로 제시하고 확인받는다.

1. 제안 분류와 그 근거
2. 반드시 좌표·크기·비율을 잠글 요소
3. 외형을 다시 그려도 되는 요소
4. 허용할 글꼴·화살표·선화 리터치 범위
5. 그대로 유지할 문자와 기호의 정확한 허용 목록
6. 예상되는 물리적 오해 또는 정답 노출 위험

교사가 `STRICT`, `MIXED`, `FLEXIBLE` 중 하나와 잠금·재묘사 범위를 명시적으로 승인하기 전에는 Image2에 입력하지 않는다. 답변이 없거나 모호하거나 본문과 충돌하면 `STRICT`로 처리하고 생성을 보류한다. 승인 내용은 문항 번호, 날짜 및 교사 표현을 함께 검수 기록에 남긴다.

유형별 생성 규칙은 다음과 같다.

- `STRICT`: 전체 재묘사를 금지한다. SVG 구조와 문자를 유지하고 허용된 글꼴·화살촉·선 마감만 제한적으로 리터치한다.
- `MIXED`: 엄격 요소는 SVG 또는 원본 레이어로 잠그고, 교사가 승인한 삽화 영역만 다시 그린다. 합성 뒤 엄격 요소의 자동 검증을 다시 수행한다.
- `FLEXIBLE`: 객체 수, 역할, 방향, 패널 대응, 라벨 및 문항 의미를 고정한 상태에서 승인된 객체 외형을 적극적으로 재묘사할 수 있다. 원본·축소 비전 검수에서 각 객체가 즉시 식별되는지 별도로 확인한다.

- 모델이 SVG MIME을 직접 지원하지 않으면 SVG를 기준 해상도의 PNG로 직접 렌더한 파일만 입력한다. 중간 캡처, 화면 스크린샷 또는 비균등 리사이즈본을 사용하지 않는다.
- SVG를 기하 기준 원본으로 계속 유지한다. 모델 출력에서 구조선, 문자, 수식, 라벨, 각도 호, 화살표, 점선, 연결점 또는 물체 외곽을 새 기준으로 추출하지 않는다.
- 편집 허용 영역을 사전에 명시한다. 허용 목록에 없는 픽셀과 객체는 모두 잠금 영역으로 간주한다.
- `STRICT`에서는 기존 객체의 위치, 중심, 외곽 상자, 가로세로 비, 상대 크기, 선 중심 경로 및 여백을 바꾸지 않는다. `MIXED`에서는 이 규칙을 교사가 지정한 잠금 요소에만 적용한다. `FLEXIBLE`에서는 교사가 승인한 재묘사 요소의 외형과 세부 비례를 바꿀 수 있으나 객체 수, 역할, 방향, 패널 대응, 접촉·지지·내부/외부 관계와 문항 의미는 바꾸지 않는다.
- 문자, 숫자, 기호 및 단위는 추가·삭제·교체·번역하지 않는다. OCR 결과를 원문 허용 목록과 대조하며, 글자 하나라도 다르면 리젝트한다.
- 문자 내용과 의미 연결은 고정하되 평가원식 조판을 위한 글꼴, 크기, 굵기, 자간, 행간, 이탤릭, 참첨자 및 라벨의 미세 정렬은 허용한다. 라벨이 원래 가리키는 객체에서 이탈하거나 구조선과 겹치면 리젝트한다.
- 영문 물리량 기호는 명조계열 수학 글꼴의 이탤릭으로, 숫자와 단위는 직립체로 표현한다. 아래첨자는 기준 문자보다 작고 낮게 배치하며 밑줄 문자처럼 보이지 않게 한다.
- 객체 수, 화살표 수와 방향, 실선·점선 구분, 점선 간격, 접점·접선·평행·수직 관계가 모두 같아야 한다.
- 화살표의 시작점, 끝점, 방향 및 의미는 고정한다. 평가원식 인쇄 가독성을 위한 선 굵기, 화살촉 길이·폭, 접합부 및 끝마감의 리터치는 허용하되 인접 객체나 라벨을 침범하지 않는다.
- 흰 배경과 검은 선을 유지한다. 불필요한 회색, 색상, 그림자, 입체감, 질감, 광택, 그라데이션, 테두리 및 워터마크를 추가하지 않는다.
- Image2 시험용 SVG와 입력 PNG의 기준 캔버스는 `1564×1006`으로 한다. 기존 `1400×900` 논리 좌표의 객체는 이동하거나 비균등 확대하지 않고, `viewBox`의 세로 흰 여백만 합계 약 `0.512` SVG 단위 확장하여 화면비를 맞춘다.
- 캔버스 화면비, 크롭 및 바깥 여백을 유지한다. 출력 해상도가 달라지면 균등 배율과 패딩으로 기준 캔버스에 정규화하되 비균등 변형은 금지한다.
- `STRICT` 및 `MIXED`의 잠금 요소는 모델 출력과 SVG 렌더를 정합한 뒤 구조선의 위치 오차가 SVG 좌표 `1 px`를 넘으면 리젝트한다. 각도·길이비·접점은 기존 자동 검증 허용 오차를 그대로 적용한다. `FLEXIBLE`은 이 좌표 오차 기준을 승인된 재묘사 요소에 적용하지 않고, 고정 문자·기호, 객체 수와 역할, 화살표 방향, 패널 대응, 물리적 접촉·지지 관계 및 정답 비노출 여부를 비전으로 검증한다.
- 원본 크기, 시험지 축소 크기 및 반투명 차이 겹침본을 모두 비전으로 확인한다. 축소본에서 선 뭉침, 라벨 오인 또는 의미 계층 변화가 있으면 리젝트한다.
- 모델 출력이 구조 보존에는 성공했더라도 SVG 직접 렌더보다 식별 가능한 품질 향상이 없으면 불필요한 재생성으로 보고 리젝트한다.
- 생성 결과는 원본을 덮어쓰지 않고 문항 번호, 버전 및 `PASS`/`REJECT` 상태를 포함한 별도 파일명으로 보관한다.
- 시험 문항의 정답, 풀이 단서 또는 원문에 없는 물리 정보를 암시하는 세부 묘사를 추가하지 않는다.
- 전체 문항 일괄 처리는 서로 다른 유형의 시험 문항이 사용자 검수를 통과한 뒤에만 수행한다.

##### 상태 흐름

문항별 상태는 다음 값만 사용하며, 이전 단계가 완료되지 않으면 다음 단계로 올리지 않는다.

1. `UNCLASSIFIED`: 문항 본문·선택지 및 그림 분석 전
2. `CLASSIFICATION_PROPOSED`: `STRICT` / `MIXED` / `FLEXIBLE` 분류와 잠금 범위를 교사에게 제안한 상태
3. `TEACHER_APPROVED`: 교사가 분류, 잠금 요소, 재묘사 요소 및 문자 허용 목록을 명시적으로 승인한 상태
4. `GENERATED_PENDING_CHECK`: 모델 출력 또는 합성 출력이 생성됐으나 자동·비전 검수 전
5. `AUTO_REJECT`: 수치, 기하, 캔버스 또는 문자 자동 검증 실패
6. `VISION_REJECT`: 원본 또는 축소 비전 검수 실패
7. `INTERNAL_PASS_USER_REVIEW_PENDING`: 자동 검증과 비전 검수는 통과했으나 교사 최종 검수 전
8. `USER_APPROVED_PASS`: 교사가 해당 시안을 최종 승인한 상태

`AUTO_REJECT`와 `VISION_REJECT` 결과는 버전별로 보관하고, 수정본은 다시 `GENERATED_PENDING_CHECK`부터 검수한다. 기준 SVG 또는 잠금 레이어가 바뀌면 기존 통과 판정은 무효이며 분류 승인 범위와 자동·비전 검수를 다시 확인한다.

##### 유형별 합성 원칙

- `STRICT`: 모델 출력은 원본을 대체하지 않는다. 문자·화살표·기하를 포함한 SVG 잠금 레이어가 최종 픽셀을 결정하며, 교사가 따로 허용한 비기하 삽화 영역이 있을 때만 모델 출력을 제한적으로 합성한다.
- `STRICT` 문자 전용 예외: 교사가 물리량 표기의 모델 리터치를 별도로 승인하면 문자만 제거한 SVG 기하 렌더를 바탕으로, 사전 정의한 문자 마스크 내부의 모델 글자 픽셀만 합성할 수 있다. 모델의 구조선·점·화살표·물체 픽셀은 문자 마스크 안에서도 폐기하며, 마스크 밖 변경 픽셀이 1개라도 있으면 `AUTO_REJECT`한다. 문자 내용, 첨자, 단위, 객체 연결, 기준점과의 상대 위치를 OCR 및 원본·축소 비전으로 다시 확인한다.
- `MIXED`: 모델이 승인된 삽화 영역을 재묘사하고, 엄격한 구조·치수·문자 레이어는 SVG에서 다시 합성한다. 모델 단독 출력이 수치 조건을 우연히 만족해도 잠금 레이어 합성을 생략하지 않는다.
- `FLEXIBLE`: 전체 장면 재묘사가 가능하지만 문자 허용 목록, 객체 수, 역할, 방향, 패널 대응 및 물리적 접촉 관계를 검증한다.

`STRICT` 문항에 교사가 승인한 비기하 삽화 영역이 하나도 없으면 모델 출력은 비교·리젝트 기록으로만 남기고, 검증된 SVG 직접 렌더를 최종 후보로 유지한다. 이는 모델 사용 횟수보다 기하 보존을 우선한다는 원칙이다.

### 6. PNG 변환

- SVG를 지정된 화면비로 직접 래스터화한다.
- 선이 흐려지지 않도록 충분한 해상도로 출력한다.
- PNG 변환 뒤 크롭이나 비균등 리사이즈로 비례를 바꾸지 않는다.
- HML에서 목표 크기로 축소할 때도 가로세로 비율을 잠근다.

### 7. 비전 기반 렌더 검수

자동 검증은 좌표와 수식의 필요조건만 확인한다. 최종 통과 판정 전에는 반드시 실제로 렌더링된 PNG를 비전으로 확인한다. SVG 코드나 검증 수치만 보고 시각 검수를 대신하지 않는다.

다음 두 크기를 모두 검수한다.

- 원본 해상도: 접점, 접선, 선의 연결 및 미세한 겹침 확인
- 시험지 삽입 예상 크기 또는 축소 미리보기: 라벨 판독성, 의미 계층 및 전체 배치 확인

비전 검수에서는 적어도 다음 항목을 확인한다.

- 각도 숫자와 각도 호가 빗면, 바닥선, 물체 또는 다른 표기에 가리거나 겹치지 않는가
- 실이 도르래의 물리적으로 올바른 쪽 접점에 닿고, 도르래를 감싸는 방향과 위·아래 관계가 맞는가
- 실, 막대, 화살표가 의도한 물체의 정확한 면 중심 또는 지정점에 시각적으로 연결되는가
- 물체의 접촉면이 빗면과 맞닿고 평행하게 보이는가
- 선의 우연한 교차, 끊김, 클리핑, 이중선 또는 뭉침이 없는가
- 라벨과 화살표가 구조선에 가려지지 않고 시험지 크기에서 구별되는가
- 문항 본문의 물리적 상태와 운동 방향이 그림에서 모순 없이 읽히는가

각 항목은 실제 렌더링에서 확인한 근거와 함께 `통과` 또는 `리젝트`로 기록한다. 자동 검증이 통과했더라도 비전 검수에서 한 항목이라도 실패하면 최종 상태는 `리젝트`이다. 수정 후에는 자동 검증, 원본 비전 검수 및 축소 비전 검수를 모두 처음부터 다시 수행한다. 세 검수가 모두 통과하기 전에는 사용자에게 승인 가능한 시안으로 보고하지 않는다.

## 자동 검증

SVG 생성 후 문항별 검증값을 계산하고 허용 오차와 비교한다.

### 필수 검증 항목

- 각도: 목표값과 계산값의 차이
- 길이비: 목표 비와 SVG 좌표 비의 차이
- 좌표: 벡터 종점 및 표시점
- 평행·수직: 방향벡터 또는 내적
- 중심 연결: 연결점과 면 중점의 거리
- 도르래 접선: 반지름과 실 방향의 내적
- 동심원과 동일 반지름 조건
- 포물선: 시작점, 초기 접선 기울기, 종점
- 라벨: 누락, 중복 및 잘못된 위치

기하 검증의 기본 허용 오차는 다음과 같다.

- 각도: `0.1°` 이하
- 길이비: `0.5%` 이하
- 연결점 및 교점: SVG 좌표 `1 px` 이하
- 평행·수직·접선 계산: 정규화 오차 `0.001` 이하

검증에 실패한 그림은 사용자에게 제시하지 않고 리젝트하여 수정한다. 자동 검증의 `PASS`는 비전 검수 완료를 뜻하지 않으며, 비전 검수 전 상태는 반드시 `VISION_PENDING`으로 표시한다.

## 문항 적합성 검수

수치 검증을 통과한 뒤 다음을 별도로 확인한다.

- 문항을 푸는 데 필요한 시각 정보가 모두 있는가
- 그림이 본문의 조건과 모순되지 않는가
- 정답이나 풀이 결과를 의도치 않게 노출하지 않는가
- 객체 수와 연결 관계가 정확한가
- 불필요한 부품, 점, 라벨 또는 화살표가 추가되지 않았는가
- 라벨이 구조선이나 다른 라벨을 가리지 않는가
- 실제 상태와 가상 상태가 실선과 점선으로 명확히 구별되는가
- 작은 시험지 크기에서도 선과 문자가 구분되는가

문제가 발견되면 해당 SVG를 수정하고 자동 검증과 시각 검수를 모두 다시 수행한다.

## 이미지 내부 콘텐츠 원칙

문자, 숫자, 기호, 단위, 수식, 라벨, 지시선, 화살표 및 방향 표시는 과학적 의미를 전달하는 경우 사용할 수 있다.

다음 내용은 넣지 않는다.

- 현상이나 장치의 작동 원리를 문장으로 설명하는 글
- 풀이 또는 해설
- 정답이나 판단 근거를 직접 설명하는 글
- 로고, 워터마크 및 출처 표기

즉, 도식의 구성 요소로 기능하는 정보 표시는 허용하되 그림을 대신하는 설명문은 배제한다.

## 참고 이미지 처리

참고 이미지는 객체 수, 연결 관계, 좌우 방향, 패널 수 및 의미 관계를 파악하는 데 사용한다.

기하 조건은 참고 이미지의 픽셀을 그대로 추종하지 않고 문항의 수치 조건으로 다시 계산한다. 권한이 불명확한 교과서나 기출문제 이미지는 그대로 복제하지 않고 동일 개념을 전달하는 새로운 SVG 도식으로 재구성한다.

## 재현 가능한 전체 작업 절차

이 절차는 새 HML을 받은 시점부터 승인된 PNG를 별도 HML 결과본에 삽입하고 검증할 때까지의 표준 작업 순서다. 각 단계의 기록과 파일을 남겨, 작업자가 바뀌거나 문항 순서가 변경되어도 같은 판단을 재현할 수 있게 한다.

### 1. 입력 동결과 작업 장부 생성

- 원본 HML, 지침 문서, 기존 SVG·PNG·검수 기록을 먼저 목록화한다.
- 원본 HML의 파일명, 바이트 크기 및 SHA-256을 기록한다. 이후 원본은 절대 덮어쓰지 않는다.
- HML 안의 `〔그림 프롬프트 시작 · 번호번〕`과 `〔그림 프롬프트 끝 · 번호번〕`을 전부 추출한다.
- 시작·끝 마커의 개수, 번호, 순서 및 중첩 여부를 확인한다. 한 쌍이라도 맞지 않으면 HML 수정 단계로 진행하지 않는다.
- 문항별 작업 장부에는 적어도 다음 항목을 둔다.

```json
{
  "newItem": 0,
  "oldItem": null,
  "promptFingerprint": "",
  "classification": "STRICT | MIXED | FLEXIBLE",
  "locked": [],
  "redrawAllowed": [],
  "teacherOverrides": [],
  "svg": "",
  "png": "",
  "width": 0,
  "height": 0,
  "sha256": "",
  "status": "UNCLASSIFIED"
}
```

`promptFingerprint`는 공백과 태그를 정규화한 그림 프롬프트의 해시로 기록한다. 문항 번호만으로 같은 문항이라고 판단하지 않는다.

### 2. 문항 순서 변경·교체 판정

- 새 HML의 프롬프트를 이전 HML 및 기존 작업 장부와 내용 기준으로 대조한다.
- 번호가 달라도 프롬프트 내용과 문항의 물리 조건이 같으면 `oldItem → newItem` 대응표를 만든다.
- 프롬프트가 일부 수정되었으면 수정된 조건이 승인 이미지에 영향을 주는지 문항 본문과 함께 재검토한다.
- 새 문항, 삭제 문항, 순서만 바뀐 문항을 명시적으로 구분한다.
- 사용자의 최신 지시는 HML 안의 오래된 프롬프트보다 우선한다. 예를 들어 삭제 승인된 라벨, 수정된 각도, 연결점 또는 화살표는 `teacherOverrides`에 원문 그대로 남긴다.
- 최신 지시와 HML 본문이 물리적으로 충돌하면 임의로 삽입하지 않고 해당 문항만 보류한다.

### 3. 기존 승인본 재사용 판정

- 이전에 `USER_APPROVED_PASS`를 받은 그림이 새 문항과 동일하면 새로 생성하지 않고 승인본을 재사용한다.
- HML에만 들어 있는 승인 이미지는 `<BINDATA>`를 추출한다. `Compress="true"`이면 HML 방식에 맞게 압축을 해제한 뒤 원본 바이트를 보존한다.
- BMP 등 HML 삽입에 불편한 형식은 PNG로 무손실 변환할 수 있다. 변환 전후의 픽셀 배열이 완전히 같은지 검증하고, 다르면 재사용 승인본으로 취급하지 않는다.
- 재사용 과정에서 자르기, 보간 리사이즈, 비균등 확대, 선 정리 또는 생성형 모델 재묘사를 하지 않는다.
- 재사용 파일에도 출처 문항, 추출 방식, 원본 해시, 변환본 해시 및 픽셀 동등성 검증 결과를 기록한다.

### 4. 신규·수정 문항 제작 루프

1. 문항 본문·선택지·프롬프트를 읽고 구조 명세를 작성한다.
2. `STRICT`, `MIXED`, `FLEXIBLE`과 잠금·재묘사 범위를 교사에게 제안한다.
3. 교사의 명시적 승인을 받은 뒤 SVG를 새 버전으로 제작한다.
4. 자동 기하 검증을 수행한다. 실패본은 `AUTO_REJECT`로 보관하고 수정한다.
5. SVG 직접 렌더 PNG를 원본 크기와 시험지 축소 크기로 비전 검수한다. 실패본은 `VISION_REJECT`로 보관하고 수정한다.
6. 승인 범위 안에서만 GPT Image 내장 경로를 사용한다.
7. 모델 출력의 캔버스, 객체 수, 라벨 허용 목록, 방향, 연결 관계 및 물리적 상태를 검사한다.
8. `STRICT` 또는 `MIXED` 잠금 요소는 SVG 레이어를 다시 합성하고, 자동·비전 검수를 처음부터 반복한다.
9. 내부 통과본만 교사에게 제시한다.
10. 교사가 최종 승인한 정확한 파일을 `USER_APPROVED_PASS`로 동결한다.

모든 시안은 원본을 덮어쓰지 않는다. 권장 이름은 다음과 같다.

- `svg/NN번_v01.svg`
- `png/NN번_v01_RAW.png`
- `png/NN번_v01_AUTO_REJECT.png`
- `png/NN번_v02_VISION_REJECT.png`
- `png/NN번_v03_USER_APPROVED_PASS.png`

### 5. 생성형 모델 출력의 추가 검증

- 도구가 실제 모델 ID를 노출하지 않으면 `GPT Image 내장 경로`라고만 기록한다.
- 요청한 캔버스와 실제 출력 픽셀 크기를 비교한다. 다르면 승인 전 정규화 방법과 결과를 기록한다.
- 정규화는 균등 배율과 흰 패딩만 허용한다. 비균등 변형과 임의 크롭은 금지한다.
- 원본 SVG 렌더와 모델 출력을 정합해 차이 영상을 만든다.
- 허용 영역 밖의 변경 픽셀이 있으면 리젝트한다.
- 문자 전용 합성은 다음 순서를 따른다.
  1. 전체 SVG 렌더와 문자 제거 SVG 렌더를 만든다.
  2. 두 영상의 차이로 문자 마스크를 만들고, 안티앨리어싱을 포함할 만큼만 제한적으로 팽창시킨다.
  3. 구조선 마스크와 겹치는 부분을 제외한다.
  4. 모델 출력에서 문자 마스크 안의 검은 글자 픽셀만 가져온다.
  5. 마스크 밖 변경 픽셀이 `0`인지 확인한다.
  6. OCR 또는 수동 대조로 문자·숫자·첨자·단위의 허용 목록 일치를 확인한다.
- 모델 결과가 SVG 직접 렌더보다 명확히 좋아지지 않으면 모델 결과를 채택하지 않는다.

### 6. 비전 검수 반복 규칙

- 자동 검증을 통과한 뒤 반드시 실제 PNG를 비전으로 본다.
- 전체 화면뿐 아니라 각도 표기, 도르래 접점, 실 연결점, 물체 접촉면, 궤적의 시작·끝, 라벨과 선의 겹침을 확대해서 본다.
- 원본 해상도와 HML 삽입 예상 크기의 축소본을 각각 검사한다.
- 문항을 직접 풀 때 필요한 정보가 그림에 맞게 주어졌는지, 반대로 정답을 노출하는 정보가 추가되지 않았는지 확인한다.
- 한 항목이라도 실패하면 해당 버전을 리젝트하고 SVG 단계에서 수정한다. 중간 합성본만 손보아 기하 기준을 잃지 않는다.
- 수정 뒤에는 자동 검증, 원본 비전 검수 및 축소 비전 검수를 모두 다시 실행한다.

### 7. 교사 승인 동결과 HML 삽입용 묶음

- 교사에게는 내부 통과본만 문항 번호순으로 한 번에 보여 준다.
- 승인된 정확한 파일을 `png/hml_ready/`에 복사한다. 이후 HML에는 이 폴더의 파일만 사용한다.
- `png/hml_ready/manifest.json`에 새 문항 번호, 이전 문항 번호, 출처, 파일명, 픽셀 크기, SHA-256, 승인 상태 및 최신 교사 수정 조건을 기록한다.
- 삽입 직전에 다음을 다시 확인한다.
  - HML의 프롬프트 마커 번호 집합과 manifest의 문항 번호 집합이 같은가
  - 모든 상태가 `USER_APPROVED_PASS`인가
  - 실제 파일의 크기와 SHA-256이 manifest와 같은가
  - 같은 파일이 실수로 여러 문항에 중복 배정되지 않았는가. 의도된 재사용은 장부에 명시되어 있는가
- 이 검사가 끝나기 전에는 HML의 프롬프트 영역을 지우지 않는다.

### 8. HML 삽입 절차

- 원본 HML은 그대로 두고 파일명에 `_그림삽입` 또는 명시된 버전 접미사를 붙인 별도 결과본을 만든다.
- HML의 XML 구조와 기존 그림 구조를 먼저 확인한다. 임의의 태그 형식을 새로 만들지 않고 해당 문서가 사용하는 `<BINDATALIST>`, `<BINITEM>`, `<BINDATASTORAGE>`, `<BINDATA>`, `<PICTURE>`, `<IMAGE>` 구조를 따른다.
- `<BINITEM>`과 `<BINDATA>`에는 서로 일치하는 고유 ID를 부여한다. 기존 ID, `InstId`, `ZOrder`와 충돌하지 않게 한다.
- 각 문항의 시작 마커가 들어 있는 문단부터 끝 마커가 들어 있는 문단까지를 하나의 교체 범위로 본다. 범위 밖의 문제 본문, 표, 수식 및 문단은 수정하지 않는다.
- 교체 범위 전체를 승인 PNG 한 장을 참조하는 `<PICTURE>` 문단으로 바꾼다.
- PNG 원본 바이트는 재인코딩하지 않고 그대로 Base64로 넣는다.
- `IMAGEDIM`, `IMAGERECT`, 원본 크기 주석에는 실제 픽셀 크기를 반영한다. HML 내부 원본 좌표는 픽셀당 `75` 단위를 기본으로 사용하되, 기존 문서의 그림 단위가 다르면 기존 문서 규칙을 따른다.
- 표시 크기는 원본 화면비를 잠그고 문서의 본문 폭 안에 맞춘다. 비균등 확대·축소와 크롭을 금지한다.
- 폭이 넓거나 세로로 긴 특수 그림은 동일한 고정 높이를 강제하지 않고 화면비에 따라 높이를 계산한다.

### 9. HML 삽입 후 자동 검증

결과본을 저장한 뒤 적어도 다음을 모두 확인한다.

- XML 파서로 오류 없이 열리는가
- 그림 프롬프트 시작·끝 마커가 모두 `0`개인가
- `<BINITEM>`, `<BINDATA>`, `<PICTURE>`, `<IMAGE>`의 신규 개수가 삽입 문항 수와 같은가
- 각 `<IMAGE BinItem="…">`가 실제 `<BINITEM>`과 `<BINDATA>`를 참조하는가
- Base64를 다시 디코딩한 PNG의 SHA-256이 manifest와 정확히 같은가
- 디코딩한 PNG의 픽셀 크기와 manifest가 같은가
- ID, `InstId` 및 새 그림의 참조가 중복되지 않았는가
- 문항 번호순 이미지 매핑이 manifest와 같은가
- 원본 HML의 SHA-256이 작업 전 기록과 같고 결과본 경로가 원본과 다른가
- 결과본을 한글에서 열어 그림 누락, 잘림, 겹침, 페이지 이탈 및 비율 왜곡이 없는지 시각 확인했는가

자동 검증 실패 시 결과본을 배포하지 않는다. 원본에서 다시 생성하며, 실패한 결과본을 다음 수정의 기준으로 삼지 않는다.

### 10. 완료 보고와 복구 기준

완료 보고에는 다음을 포함한다.

- 보존된 원본 HML과 생성된 결과 HML의 경로 및 SHA-256
- 적용한 manifest 경로와 삽입 문항 수
- 문항별 최종 PNG 파일명과 해시
- 프롬프트 마커 제거 개수 및 그림 참조 검증 결과
- 자동 검증으로 확인하지 못해 한글에서 수동 확인해야 하는 항목

문제가 발견되면 승인 PNG와 manifest는 유지하고, 보존된 원본 HML에서 새 결과본을 다시 만든다. 이미 수정된 HML 위에 누적 패치를 적용하지 않는다.
